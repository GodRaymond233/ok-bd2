# ok-bd2 新桌面客户端 · 本地测试包说明

这个测试包通过本地更新仓库验证 Electron 客户端，复用 Python 自动化核心。

## 阶段 5：更新、备份与恢复

- 设置 → 关于与更新：检查当前测试仓库的新版本，确认后停止任务、等待核心与写入线程退出，生成完整配置备份，再交给当前安装的 PyAppify 更新。不会关闭游戏。核心收尾或备份失败时停止更新。
- 同页可创建备份、查看备份列表，并恢复与当前核心版本匹配的备份。恢复将整体替换配置、方案、账本和运行记录，先保存当前数据；完成后停在提示页，由你点击退出，从启动器重新打开后再核对并运行任务。
- 安装版的备份位于 `data/apps/ok-bd2/backups/`，在 `working/` 外；源码运行的手动备份位于 `.local-dev/backups/`。保留最近 5 份有效备份。每次核心版本变化时，在加载配置前自动备份；首次迁入的旧配置标记为未知版本，不提供一键恢复。
- 备份目录包含完整配置，可能含通知渠道凭据，仅供本机恢复，请勿作为问题报告发送。
- 降级到旧核心前，应先退出所有客户端。可用新版本随包工具从安装的 `working/` 目录执行 `..\python\python.exe -m src.desktop.maintenance restore --version <备份对应版本> --backup-id <备份编号>`，恢复后再在启动器切回该版本，避免先让旧核心加载新数据。备份之后的进度和设置不会合并；新版入口会阻止直接加载来自较新核心的数据。没有验证过的版本组合不声明兼容。
- 启动器重新安装、国内/海外配置切换会在核心启动前删除 `working/`；核心启动备份无法保护此前已删除的配置，必须提前备份。这项启动器行为仍需单独验收。
- PyAppify 的启动器单实例跨安装共享；检查更新和更新交接会核对当前启动器归属，其他安装的启动器正在运行时拒绝操作。

外壳缺失时，引导程序读取随核心发布的 `src/desktop/shell-release.json`，按固定版本和 SHA256 下载、检查解压路径后安装到独立版本目录；旧外壳保留。下载或校验失败不启动核心。测试清单只指向本地 ZIP，正式源必须使用 HTTPS。

## 分发产物

先构建 `desktop/ui` 与 `desktop/shell`。选择自建打包步骤：PyAppify 完成 setup 后，用以下脚本生成外壳 ZIP 和核心下载清单，并把已校验的外壳放入完整包，再执行最终归档：

```powershell
.\.venv\Scripts\python.exe desktop/scripts/build-shell-release.py --output <产物目录> --manifest <更新树>/src/desktop/shell-release.json --url <国内HTTPS地址> --url <海外HTTPS地址> --offline-app-base <完整包>/data/apps/ok-bd2
```

本地试验将 `--url` 换为 `--local`；`build-test-package.ps1` 自动生成本地下载清单。ZIP 内固定时间戳；同输出目录中同版本不同内容会拒绝覆盖，正式分发前应提升外壳版本。清单随核心和前端构建产物同步，完整包包含外壳，在线包允许启动前下载。外壳版本变化时同步修改 bootstrap 与 shell package/lock，重跑 Windows 检查；运行时安全升级沿用此流程。

`windows-checks.ps1` 包含四种真实 Electron 维护探针：更新交接、恢复、缺少安全退出凭据、备份失败。使用生成配置，启动器由记录替身接管；不等于真实启动器安装、国内/海外下载或干净 Windows 10/11 验收。正式 CI 与公开分发仍按项目发布流程接入。

以下保留最初测试包的组装和 U1–U10 操作参考；旧版本号与“验证页”名称以实际安装版为准。断网启动已由用户决定跳过。

## 安全边界

- 测试包是一个独立文件夹，和你正在用的 ok-bd2 互不影响。它不读写正式安装目录。
- 启动器的更新源指向文件夹里的 `update-repo.git`（本地测试仓库），不会访问 cnb.cool 或 GitHub 的正式更新源。
- 配置和账本只放**副本**。不要把正式安装的 `configs` 文件夹直接移进来。
- 新客户端只结束它自己启动的进程，不会结束游戏、Starter 或启动器。

## 文件夹结构

```text
<测试包>\
  ok-bd2.exe                     启动器（v1.3.19 发布包里的 PyAppify v1.2.3，已校验 SHA-256）
  pyappify.yml                   测试用启动器配置（更新源 = 本地测试仓库，入口 = main_desktop.py）
  update-repo.git\               本地测试仓库（tag v0.9.0；U10 再加 v0.9.1）
  test-package-notes.md          本说明
  logs\                          启动器日志（app.<日期>）
  data\apps\ok-bd2\
    working\                     核心代码与 configs\、logs\（由启动器同步）
    python\                      启动器安装的 Python 3.12
    shell\0.1.0\                 Electron 外壳（不在 working\ 里，代码同步不会动它）
    shell-data\                  外壳的浏览器数据
```

日志位置：

| 日志 | 位置 |
|---|---|
| 外壳日志 | `data\apps\ok-bd2\working\logs\desktop-shell.log` |
| 核心日志 | `data\apps\ok-bd2\working\logs\` 下的其他文件 |
| 启动器日志 | `logs\app.<日期>`（测试包根目录下，不在 `data\` 里） |

验证页右上角的"打开日志文件夹"会直接打开核心日志所在的文件夹。

## 组装（Codex 或你在 Windows PowerShell 中执行）

```powershell
cd D:\ok-bd2-worktrees\electron-client
powershell -NoProfile -ExecutionPolicy Bypass -File desktop\scripts\windows-checks.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File desktop\scripts\build-test-package.ps1 -Output D:\ok-bd2-desktop-test
```

- 第一条命令跑完整检查并打包外壳；第二条组装测试包，过程中启动器会弹 UAC，并下载 Python 和依赖（需要联网）。
- 想带上配置副本：先把正式配置**复制**到别处（例如 `D:\bd2-config-copy`），再加参数 `-ConfigCopy D:\bd2-config-copy`。
- 目标文件夹已经存在时，脚本会拒绝继续。如果中途失败，请先手动删除这个文件夹，再重新运行。

## 启动与退出

- 启动：双击 `ok-bd2.exe` → 同意 UAC → 在启动器里点"启动"。先看到"正在启动 ok-bd2"，随后出现"ok-bd2 链路验证"页。
- 退出：右键托盘图标 →"退出"，或者直接关窗口，或者点验证页的"退出"。这三种都走安全退出。

## 需要你配合的验证项（U1–U10）

每一项都写了操作、预期结果和需要回传的内容。不符合预期就停下，把回传内容发给我。

### U1 启动（不需要游戏）

1. 关掉游戏，双击 `ok-bd2.exe` 并启动。
2. 预期：验证页的"连接 → 核心接口"显示"正常"，"游戏窗口与截图方式"显示"未找到游戏窗口"。
3. 退出后断开网络，再启动一次，预期结果相同。

回传：两次启动的截图；任务管理器"详细信息"页中 `ok-bd2-desktop.exe` 和 `python.exe` 的截图；外壳日志。

### U2 正常退出（不需要游戏）

1. 先记下任务管理器里的 `ok-bd2-desktop.exe` 和 `python.exe`，然后用托盘"退出"。
2. 预期：20 秒内这些进程全部消失。

回传：退出前后的进程截图。

### U3 异常情况（不需要游戏）

1. 在任务管理器里结束 `ok-bd2-desktop.exe`（只结束这一个进程，不要选"结束进程树"）。预期：属于测试包的 `python.exe` 在 20 秒内消失。
2. 重新启动，然后结束属于测试包的 `python.exe`。在"详细信息"页右键表头 →"选择列"→ 勾选"命令行"，命令行里带 `--service` 的那个就是核心。预期：外壳显示"自动化核心意外退出"和"重新启动核心"按钮；点按钮后验证页恢复。
3. 客户端运行时，再从启动器启动一次。预期：只会把已有窗口调到前台，不会出现第二个窗口。

回传：核心日志和外壳日志；每一步的截图。

### U4 连接游戏（需要游戏）

1. 先手动打开游戏，再启动客户端（或在验证页点"刷新窗口"）。
2. 预期："游戏窗口与截图方式"的"窗口"显示 `PC 已连接：BrownDust II 1920x1080`（分辨率按实际窗口），"截图方式"显示实际在用的方式，默认配置下是 `WGC（自动选择）`。没有找到游戏窗口时，"截图方式"显示"未使用"。

回传：截图。

### U5 自动登录（需要游戏）

在验证页的任务列表里，启用自动登录，再停用它。观察"状态"一栏，以及"实时日志"里的变化。

回传：日志。

### U6 白嫖抽抽乐（需要游戏）

1. 让游戏停在主页，然后在任务列表里点开始。
2. 预期：任务从头跑完；状态、阶段信息和日志实时更新；结束后执行器回到空闲。
3. 确认运行记录已写入 `working\configs\` 下。

回传：日志和运行记录文件的副本。

### U7 一键日常中途停止（需要游戏）

1. 开始一键日常，在第 1–2 个子任务时点"停止当前任务"。
2. 预期：游戏不再被点击；子任务状态正确；运行记录里没有把没做完的项目记成完成。

回传：日志，可选录屏。

### U8 游戏不被误杀（需要游戏）

在 U4–U7 任一时刻，先结束外壳；再重新启动，然后结束核心。

- 预期：游戏一直在运行。
- 之后重新启动的客户端能正常开始任务，说明执行器锁已释放。

回传：前后的进程截图。

### U9 执行器锁与旧版（部分需要游戏）

启动器只允许开一个（见"已知限制"）。第 2、3 步要求正式版和测试包同时运行，开始前先和 Codex 确认第二个程序从哪里启动。

1. 新代码的两个入口：客户端运行时，在 PowerShell 执行下面的命令（`<测试包>` 换成实际路径）。预期：弹出"……正在控制游戏。同一时间只能运行一个 ok-bd2，请先退出它。"，然后这个窗口退出。

   ```powershell
   cd <测试包>\data\apps\ok-bd2\working
   ..\python\python.exe main.py
   ```

2. 旧版先运行：先打开你正式安装的 v1.3.19，再启动测试包。预期：验证页顶部出现黄色提示"检测到正在运行的旧版 ok-bd2……"；在验证页点开始任务会被拒绝；旧版不会被结束。
3. 新版先运行：先启动测试包，再打开 v1.3.19。预期：旧版仍能打开（这是已知限制，旧版不认识新锁）。新版下次开始任务时会提示并拒绝。

回传：截图和日志。

### U10 数据保留与本地更新（不需要游戏）

1. 先完全退出客户端（托盘"退出"）。
2. 由 Codex 或你添加一个更新版本：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File desktop\scripts\build-test-package.ps1 -Output <测试包> -AddUpdateTag
   ```

3. 启动 `ok-bd2.exe`，按启动器提示更新到 v0.9.1，然后启动。
4. 检查：
   - 验证页顶部"核心"后面的版本是 v0.9.1；
   - `working\configs\`、`shell\0.1.0\`、`shell-data\` 都还在；
   - 在启动器日志 `logs\` 里搜索 `cnb.cool` 和 `github.com`，应该没有结果。
5. （可选，只用副本）在启动器里切换配置（国内 ⇄ 海外，两个配置都指向本地仓库），记录 `working\configs\` 是否被删除。

回传：更新前后的目录列表，以及启动器日志。

## 已知限制（阶段 1）

- 这是验证页，不是正式界面。方案编辑、运行历史列表、截图预览、快捷键、关闭到托盘、通知和更新界面都不在本阶段。
- 关闭窗口就是退出客户端。
- 启动器在更新时会强制结束 `data\apps\ok-bd2\` 下的全部进程。"准备更新"（先停任务、保存）要到后续阶段才实现，所以 U10 要求先手动退出客户端。
- 启动器"安装/切换配置"会先删除整个 `working\`，`working\configs\` 也会一起删除。这是现有启动器的行为，新核心的配置备份无法保护首次启动前就被删掉的文件。所以测试包只放副本。
- 旧版（v1.3.19）不认识新的执行器锁。新版只检测旧版、拒绝开始任务，不会结束旧版。
- 外壳没有签名，Defender 可能会提示。
- **开始菜单快捷方式会被测试包改写。** 启动器每次成功启动应用后，都会按应用名重写开始菜单里的 `ok-bd2.lnk` 和 `ok-bd2 启动器.lnk`；桌面上已经有 `ok-bd2.lnk` 时，桌面上这两个也会被改写。测试包和正式版的应用名都是 `ok-bd2`，所以测试包启动过之后，这些快捷方式指向测试包。测试期间请直接双击各自文件夹里的 `ok-bd2.exe`，不要用开始菜单或桌面的 ok-bd2 入口。测试结束后，用正式版文件夹里的 `ok-bd2.exe` 正常启动一次，它会把快捷方式改回正式版。
- **测试包和正式版的启动器不能同时开着。** 两个启动器是同一个程序，只允许开一个：另一个已经开着时，再双击 `ok-bd2.exe` 只会把已经开着的那个调到前台。客户端运行期间启动器也一直开着，所以要换另一边时，先退出客户端并关闭它的启动器。
- 删除测试包：退出客户端后，直接删除整个文件夹。删除前先按上面"开始菜单快捷方式"一条把快捷方式改回正式版，否则开始菜单里的 ok-bd2 入口会失效。
